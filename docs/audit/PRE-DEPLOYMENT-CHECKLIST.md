## 7. Rollback procedure

1. **Code:** Actions → **Roll back Hostinger release**:
   - target `production`;
   - `restore_previous_site` = `false`.

   The reviewer approves. `current` returns to `5d76858`. There are no migrations to undo.
2. **Database:** the code rollback does not undo the 30 imported fact decisions.
   - The old code has no register gate. Any published school with 5/5 core facts would then be indexed: the nine RESEARCH schools above, besides Cambridge, King's College London and Queen's Belfast, which stay indexed either way.
   - To prevent that, do one of:
     - **(a)** unpublish those nine schools in Admin → Universities (reversible). **Recommended.**
     - **(b)** restore the pre-deploy dump `~/backups/production-db-<timestamp>.sql.gz`. Its name is printed as "db backup verified:" in the deploy log. This also undoes anything students or staff did after the deploy.
3. **Verify:** run Live Verification and compare its sitemap with the 36 live URLs recorded in §3.
